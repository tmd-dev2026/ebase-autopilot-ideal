# 理想のオートパイロット(構想サイト)

本物の eBase Autopilot を、初めての人から上級者までが使いやすく、人間の作業負担が減る形に作り直した場合の試作です。**構想であり、本物にはまだ反映されていません。** 外部サービスには接続せず、ダミーのデータだけで動きます。体験版(説明会用)とは別のサイトです。

設計の土台と仕様は開発チームの資料にあります(社内)。試作の印: 現行 / 改 / 新 / 将来。

## Stage 1：シェルと「今日」

`index.html` をそのままブラウザで開けます（file:// 対応）。GitHub Pagesでもビルド不要・相対パスで動きます。外部通信はありません。全メニューのルートを用意し、「今日」以外は次段階の明示的な仮画面です。

「今日」は要修正3件・未返信2件・オファー1件・発送待ち2件・仕入れ元終了1件の例から開始します。確認、追跡入力、処理、元に戻す、自動処理ON/OFFを試せます。赤字の承諾・再提案は止めます。メッセージ・価格提案・取り下げは実行前に確認します。処理状態は再読み込みで初期化され、モードとテーマだけ保存します（保存できない環境でも動作）。為替は ¥155 / $1（例）。

商品は既存の6件と写真を参照し、変更していません。データ・件数は `assets/js/data.js`、試作の印と対応説明は `assets/js/marks.js` に集約しています。スマホは下タブと「もっと」、デスクトップは常時表示の作業順メニューです。上級では j / k で項目移動、Enterで開閉、Tabで項目内の操作へ移動します。? で操作説明を開きます。

検証（Nodeのみ・依存なし）：

```sh
node tests/app.test.js
node tests/static.test.js
find assets/js tests -name '*.js' -exec node --check {} \;
```

最小のfake DOMによるルート・イベント・確認・取り消しの検証と、純粋関数・静的検証を含みます。ブラウザ検証は未実施です。360〜1440pxでの横あふれ、実ブラウザのフォーカス・ダイアログ・読み上げ・タップ操作、file://とPagesでの実表示は別途確認が必要です。人による課題達成時間や初心者の理解も未検証です。


## Stage 1b：表示の整理

ヘッダーを1行にまとめ、スマホのモード・テーマ・操作ヘルプは「表示」に集約しました。検索アイコンで入力欄を開き、テーマは自動→ライト→ダークの順で切り替えます。印は非操作の小さなチップにし、説明は構想バッジとフッターの「印とは」から開きます。

「今日」に対応済み件数、カテゴリへの移動、商品ごとの要点と専用の操作ボタンを追加しました。自動処理はスイッチと折りたたみ説明、停止時の影響を表示します。見込みは破線、確定は実線で区別します。発送先・期限・仕入れ終了理由もダミーデータです。既存の確認・取り消し操作は維持しています。Stage 1bもNodeのみで検証し、実ブラウザの幅・テーマ別表示は未検証です。
