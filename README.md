# 理想のオートパイロット(構想サイト)

本物の eBase Autopilot を、初めての人から上級者までが使いやすく、人間の作業負担が減る形に作り直した場合の試作です。**構想であり、本物にはまだ反映されていません。** 外部サービスには接続せず、ダミーのデータだけで動きます。体験版(説明会用)とは別のサイトです。

設計の土台と仕様は開発チームの資料にあります(社内)。試作の印: 現行 / 改 / 新 / 将来。

## Stage 1：シェルと「今日」

`index.html` をそのままブラウザで開けます（file:// 対応）。GitHub Pagesでもビルド不要・相対パスで動きます。外部通信はありません。全メニューのルートを用意し、「今日」「作る」「出品管理」「注文・発送」「メッセージ」「返品とクレーム」「ウォッチャーとオファー」「広告」「収益とレポート」を実装済みです。その他は次段階の明示的な仮画面です。

「今日」は要修正3件・未返信2件・オファー1件・発送待ち2件・仕入れ元終了1件の例から開始します。確認、追跡入力、処理、元に戻す、自動処理ON/OFFを試せます。赤字の承諾・再提案は止めます。メッセージ・価格提案・取り下げは実行前に確認します。処理状態は再読み込みで初期化され、モードとテーマだけ保存します（保存できない環境でも動作）。為替は ¥155 / $1（例）。

商品は既存の6件と写真を参照し、変更していません。データ・件数は `assets/js/data.js` と `assets/js/data-aftersale.js`、試作の印と対応説明は `assets/js/marks.js` に集約しています。スマホは下タブと「もっと」、デスクトップは常時表示の作業順メニューです。上級では j / k で項目移動、Enterで開閉、Tabで項目内の操作へ移動します。? で操作説明を開きます。

検証（Nodeのみ・依存なし）：

```sh
node tests/app.test.js
node tests/static.test.js
find assets/js tests -name '*.js' -exec node --check {} \;
```

最小のfake DOMによるルート・イベント・確認・取り消しの検証と、純粋関数・静的検証を含みます。ブラウザ検証は未実施です。360〜1440pxでの横あふれ、実ブラウザのフォーカス・ダイアログ・読み上げ・タップ操作、file://とPagesでの実表示は別途確認が必要です。人による課題達成時間や初心者の理解も未検証です。


## Stage 1b：表示の整理

ヘッダーを1行にまとめ、スマホのモード・テーマ・操作ヘルプは「表示」に集約しました。検索アイコンで入力欄を開き、テーマは自動→ライト→ダークの順で切り替えます。印は非操作の小さなチップにし、説明は構想バッジとフッターの「印とは」から開きます。

「今日」に対応済み件数、カテゴリへの移動、商品ごとの要点と専用の操作ボタンを追加しました。自動処理はスイッチと折りたたみ説明、停止時の影響を表示します。見込みは破線、確定は実線で区別します。発送先・期限・仕入れ終了理由もダミーデータです。既存の確認・取り消し操作は維持しています。Stage 1bもNodeのみで検証し、実ブラウザの幅・テーマ別表示は未検証です。


## Stage 2：作る・出品管理

「作る」は3件の未出品例から、元情報・英語の編集・購入者向けプレビュー・自動検証・出品／予約までを1画面で試せます。停止理由はその場で修正し、上級だけ赤字に限って理由と背景を記録して出品できます。カテゴリ選択も判断の履歴に残ります。上級の `p` は入力中以外に出品します。

「出品管理」は12件の例、検索・状態の件数・並べ替え・上級の条件保存・原因と原文・一括操作の影響プレビュー・元に戻すを備えます。出品した下書きが一覧に加わり、一覧の修正と「今日」・メニューバッジは同じデータを参照します。リセットは「対象外」の区分内で「AI処理済」と表示し、予約を作りませんが自動出品設定によって後で対象になる旨を表示します。画面は `IdealScreens` に登録し、未実装ルートは仮画面を維持します。

判断・下書き・予約・出品・保存した絞り込み・自動修正の例はセッション内だけで、再読み込みで初期化します。手数料と為替は例で、正の費用が不明・ゼロなら計算を止めます。実際の出品や送信は行いません。

全検証：

```sh
for file in tests/*.test.js; do node "$file" || exit; done
find assets/js tests -name '*.js' -exec node --check {} \;
```

Stage 2もブラウザ未使用。表示幅・ダークテーマ・フォーカス・モバイルの固定バー・読み上げ・実タップ・課題達成時間は実ブラウザと人による確認が必要です。

## Stage 3：売れたあと・改善（BRIEF6）

注文・発送、メッセージ、返品とクレーム、ウォッチャーとオファー、広告、収益とレポートを実装しました。注文6件、会話5件、ケース2件、ウォッチャー6行、広告5行を同じ6商品の写真で表示します。今日の発送・未返信・受信オファーと各画面は同じレコードを参照し、処理・元に戻すでメニューバッジも更新します。

追跡番号は共通の入力部品・保存先・検証を使い、発送登録前に通知と取り消せない影響を確認します。英語の原文はそのまま表示し、41%の返信案は人の確認を求めます。メッセージは宛先と実際に送る文面を確認してから送信します。上級の受信箱は j/k・Enter・r に対応します。返金は金額と返金後の手残りを表示した後、独立した明示ボタンでダミーデータだけを更新します。実際の返金APIは将来です。

ウォッチャーは出品管理の価格・費用・掲載状態に連動します。出品中でないもの、赤字・不明値・ウォッチャー0人への送信は止めます。割引は元の出品価格を変更せず、送信ログに記録します。広告スイッチは表示への影響を明示し、元に戻せます。

集計期間は2026年10月19〜25日、期限判定日は10月20日という固定の例です。確定は期間内の完了注文の実費と返金額から計算し、未完了は合計から除きます。見込みは出品中の各商品の手残り×販売割合25%（例）。送料比較は期間内の全注文を表示し、実送料が判明した分だけ差額を合計します。仕入れ待ち注文の実送料は不明（—）です。返金による手数料の返還は想定せず、送料・仕入れ値も残る前提を明示しています。今日の週次数値にも同じ集計関数を使います。

`aftersale.js` はDOMに依存しない計算・検証、`data-aftersale.js` は共有レコードと一度だけ実行できる確認処理、`aftersale-ui.js` は共通表示・確認部品です。`tests/aftersale.test.js` と `tests/stage3.test.js` で境界値、確認なしの操作禁止、変更された影響の再確認、両画面からの操作・取り消し、HTMLエスケープ、キーボード操作、集計の一致を検証します。旧テストは新しい実装済みルート、発送の確認、計算された週次数値に合わせて更新しています。

ブラウザは使用していません。実表示・フォーカス・読み上げ・タップ・360〜1440pxの横あふれ・ライト/ダークの視覚確認は未検証です。外部接続・コミット・公開は行っていません。

Stage 4a（BRIEF8）: 判断軸・自動処理・eBay連携と初期設定を実装。
判断軸は保存前に既存出品と未公開下書きへの影響を表示し、理由と変更前後を共有の判断履歴へ保存します。
利益率は共通 takeHome の手残り ÷ 売値の円換算。影響件数は変更によって新たに基準に触れる商品を数えます。
値下げの下限を下げる＝許容値下げ率を増やす変更は影響なし、許容率を狭める場合は元価格との差を確認します。
返信のトーンは各文体の英語例と選択中の文体を表示します（AI生成・実送信は行いません）。
自動処理は今日と同じ状態を使い、OFFのみ影響確認、変更後は元に戻せます。履歴・時刻は固定の例です。
設定の完了状態は今日のチェックリストと共有し、切断デモは影響と再連携手順を表示します。
その場の用語ボタンはタップ・Enter・Spaceで開き、Escで閉じてフォーカスを戻します。
ヘルプはショートカット・検索できる用語集・既知の不具合（困ったパネルと同一データ）を表示します。
追加検証: `node tests/criteria.test.js` / `node tests/stage4a.test.js`。全JSの `node --check` と全 `tests/*.test.js` も実行します。
ブラウザ・実機でのレイアウト、読み上げ、タップ、ライト/ダーク表示は未検証です。ネットワーク・実連携・コミットなし。

Stage 4b（BRIEF9）: リサーチ・候補・取り込みを実装し、判断軸・自動処理・初期設定の表示を整理しました。
リサーチは架空市場の8件（既存写真6件、写真なし2件）。国内送料・国際送料・関税を送料の合計として既存の takeHome に渡し、作るでも同じ総費用を引き継ぎます。利益率と避ける商品の判定は IdealCriteria を共有します。
赤字・避ける設定は全モードで取り込み停止。利益率の下限未満だけ、上級で3文字以上の理由を記録すると取り込めます。候補と取り込み状態はセッション内で保持し、同一商品のURLは末尾スラッシュ・スキームの有無にかかわらず重複として扱います。
URLの取得中→完了／失敗はローカルの例です。対応サイトの存在しない商品と未対応サイトを区別し、売れた例・相場情報には将来の印と取得制約を表示します。実通信はありません。
判断軸は一枚の設定カード内で編集し、影響件数を出品／下書き別に表示、6件目以降を折りたたみます。自動処理はPCで2列、初期設定は未完了行だけ次の一手を表示します。
